# ComPort Documentation Reviewer Skill

## Purpose

Use this skill for ComPort documentation, defense preparation, manuscript writing, README improvement, and reviewer creation.

Documentation must be accurate, beginner-friendly, professional, and based strictly on the repository.

## Core Rules

1. Strictly use repository evidence.
2. Do not hallucinate features, APIs, database tables, flows, or technologies.
3. If something is unclear, write: Not explicitly shown in the repository.
4. Use clear and beginner-friendly explanations.
5. Keep tone professional and academic when needed.
6. Explain technical terms simply.
7. Organize content with proper headings.
8. Include role-based flows when relevant.
9. Separate confirmed facts from assumptions.
10. Do not overclaim system capabilities.

## OOP Explanation Guidelines

Explain:
- classes/modules/services used in the project
- encapsulation
- abstraction
- inheritance, only if explicitly present
- polymorphism, only if explicitly present
- where OOP is visible in the codebase
- if a pillar is not strongly shown, say so honestly

## API Explanation Guidelines

For APIs:
- group by feature
- explain purpose
- explain who can use it
- explain request/response behavior if visible
- avoid inventing endpoints
- mention unclear details honestly

## Manual Writing Guidelines

For user manuals:
- use step-by-step instructions
- use beginner-friendly wording
- separate instructions by role
- include expected results
- include common errors if known

## Before Finishing

Verify:
- claims match repository evidence
- role flows are accurate
- features are not invented
- wording is clear
- formatting is professional
